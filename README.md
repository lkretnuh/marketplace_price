# Ценоскоп

Первая рабочая версия локального веб-приложения для сравнения предложений Ozon, Wildberries, Яндекс Маркета и AliExpress. Python 3.12+, SQLite и обычный браузер; сторонние зависимости не нужны.

## Запуск

Скачайте ZIP через **Code → Download ZIP** на GitHub, распакуйте его и откройте терминал в папке с `app.py`.

```sh
python3 app.py
```

На Windows можно запустить `start-windows.bat` или выполнить `python app.py`. Затем откройте **http://localhost:8000** в обычном браузере. Подробная инструкция — `START_HERE.txt`.

В локальном окружении откройте порт 8000 в браузере. По умолчанию сервер слушает только 127.0.0.1. Облачная среда может не предоставлять доступ к локальному интерфейсу. Параметры: `--host`, `--port`, `--db`. Не публикуйте сервер в интернете: эта версия рассчитана на одного доверенного пользователя, без авторизации и production-сервера.

База создаётся автоматически в `data/prices.sqlite3` (или `PRICE_DB`). Исходно она пустая. Демо включается отдельной кнопкой, явно помечено и доступно только для просмотра; его можно удалить. Реальные товары и демоданные не смешиваются внутри одного товара.

## Что работает

- Группы товаров по названию, модели и комплектации.
- Переходы к поиску по названию на четырёх площадках. Это поиск **на сайтах маркетплейсов**, а не единая выдача внутри приложения.
- Добавление карточек по HTTPS-ссылкам; несколько продавцов/карточек одной площадки видны отдельными строками.
- Ручные наблюдения: цена, доставка, диапазон дней получения, город, условия оплаты и скидок. Санкт-Петербург и RUB по умолчанию.
- Неизменяемая история наблюдений с временем записи (отображение по Москве), график за 7/30 дней и всё время, точные значения в журнале.
- Сравнение итоговой цены с доставкой и сортировка по максимальному сроку доставки, фильтры города и площадки. Истории разных городов не объединяются.
- SQLite сохраняет данные между перезапусками. Суммы хранятся целыми копейками.

Сроки доставки — оценка, введённая на момент наблюдения, а не актуальный обещанный срок площадки. Сравнивайте одну комплектацию и одинаковые условия оплаты; автоматической проверки эквивалентности нет. При отсутствии наблюдения для города предложение не участвует в сравнении. Фильтр периода относится к графику; таблица показывает последнее наблюдение выбранного города.

## Пока не реализовано

Единый поиск по ассортименту площадок, автоматический сбор и расписание обновлений, уведомления, наличие товара, конвертация валют, экспорт и аккаунты. Карточки и цены **не загружаются** по вставленной ссылке: данные вносит пользователь. Результаты сравнения отражают сохранённые наблюдения и могут устареть.

Для автоматического поиска/сбора нужно выбрать и проверить разрешённый источник данных для каждой площадки: официальный API/партнёрский фид либо поставщик данных с нужными правами. API продавца нельзя заранее считать источником всего потребительского каталога. Не предполагаются обход CAPTCHA, использование чужих сессий или гарантированная доступность публичных страниц. Ключи не нужны для текущей версии и не должны попадать в Git.

Следующий этап: проверить источники → адаптеры поиска и нормализации карточек → фоновый сбор с ограничением частоты и журналом ошибок → актуальность/наличие и уведомления. Для автоматического сопоставления обязательно учитывать модель, цвет, размер, комплект, состояние и валюту. До подтверждения пользователем предложения остаются отдельными карточками.

## Проверки

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
```

Тесты проверяют HTTP-сценарий создания товара, нескольких карточек, историю и хранение копеек, персистентность, города, ошибки входных данных, каскадное удаление, ограничения демо и запрет межсайтовой записи. Тесты используют временные базы.

Для резервной копии остановите приложение и скопируйте весь каталог `data/`. Во время работы используйте SQLite backup API, а не копирование одного файла открытой WAL-базы.
